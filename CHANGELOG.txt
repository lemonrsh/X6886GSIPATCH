v13 (2026-11-09) - "both presets are 1100": the two limits below the nodes we write
* After v12 every index and every kHz parameter could read back perfectly, the daemon
  re-published them every 15 s, and the GPU could STILL sit at 1100 MHz in BOTH presets.
  Two limits live below the two nodes this script writes, and neither is visible in them:
  (a) /proc/gpufreqv2/fix_target_opp_index - a pinned target OPP. 0..n pins, -1 releases.
      A stale pin (vendor power HAL after a thermal event) freezes the clock whatever the
      preset asks for. Now released on every reapply, re-checked in the loop every 15 s,
      and restorable with 'revert'.
  (b) the driver's own table can be CLIPPED by a platform limiter (limit_table). v12 then
      read that clipped view as "the top OPP is 1100000" and dutifully re-published
      gpu_cust_upbound_freq=1100000 every 15 s - re-applying the very cap it exists to
      lift. top_khz() now takes the MAX of the configured top and the live table, so a
      clipped table can never drag the published top down.
* ceil 0 / resolve_opp 0: "the top OPP by name" now means the CONFIGURED top, not the
  highest entry a limited driver happens to publish.
* NEW 'cap' (alias 'why'): audits every source of a ceiling in one screen - driver table
  (marked CLIPPED when short), limit_table rows, hal index, kHz parameter, pin state - and
  releases a stale pin. 'unpin' does the release on its own.
* reapply verifies the ceiling from the outside: a matching readback is not proof, so if
  the kernel kept a lower bound it says so and points at 'cap' instead of reporting success.
* status grows two lines: 'pin:' when a pin is holding the clock, and 'cap:' when the
  driver's own table is shorter than the configured top.
* ceil_to falls back to what the kernel does accept, and names the limiter when it refuses.
* The loop now asserts the ceiling and the pin on its FIRST tick, not 15 s in: the reload,
  ceiling and pin checks share one cadence (_n - 1). Nothing is lost if the phone is
  rebooted a few seconds after boot completes.
* New config keys: UNPIN=1 (release stale pins), KEEP_PIN=0 (set to 1 to respect a pin
  someone made on purpose). Revert restores a pin we released.
* Tests: 57 (was 45), incl. clipped-table, pin state/release and the "released before the

  always applies the answer; the main patch only enables its governor when a key is
  actually pressed, so an unattended flash changes nothing.
* Thermal limit is now a single point: TEMP_MAX=500 (50 C battery). Nothing at all is
  throttled below 50 C - 43 C and 49 C keep the full floor - and at/above 50 C the floor
  drops to HOT_HZ (default = lowest OPP) until the phone cools. Existing configs with
  TEMP_MAX=430 are migrated to 500 by the installer; the log and messages now print
  degrees Celsius instead of deci-degC.
* BAT_MIN=15 (safer): below 15% and not charging, the floor is not raised.
* FIXED (found testing v11.5 on the device, ladder denied): 'preset stock' refused, so
  there was no way out of 'preset max' except a reboot. 'safer'/'stock' now resolve to
  TOP_INDEX (lowest OPP) offline, and the loop's releases go there too instead of leaving
  MODE=adaptive pinned at the top after load ended.
* FIXED: a preset that cannot be applied no longer rewrites gpu.conf first; presets
  resolve the index before touching the config, so a refused preset leaves the running
  governor's policy alone. write_floor() split out of floor_to() (resolve != write).
* Screen detection: DRM dpms node -> dumpsys mWakefulness -> safe default "on" (never
  guesses off, so a missing node cannot silently keep the GPU slow).
* Tests: 36 host cases (bash + dash), incl. the safer precedence table, the 50 C
  threshold (43/49 keep full, 50/52 throttle) and the volume-key mapping.

v11.5 (GPU ceiling control + works on locked-down /proc)
* WHY: on the reporter's GSI, /proc/gpufreqv2/* is denied to the shell even as root (the
  vendor power HAL keeps its own label). 'preset max' therefore saved its config and wrote
  nothing, and the loop was inert. Separately, the real wall turned out to be GED's upper
  bound: gpu_cust_upbound_freq was 1100000, so no floor could ever give 1600 MHz.
* 'preset max' now works with no ladder at all: index 0 is the driver's own name for the
  fastest OPP, so the floor (custom_boost_gpu_freq) AND the ceiling
  (custom_upbound_gpu_freq) are written as 0, with gpu_cust_boost_freq /
  gpu_cust_upbound_freq kept in sync. boost/stock refuse on such a build instead of
  writing a guessed index.
* New CEIL_HZ (default 1600000, 0 = fastest OPP): the governor publishes GED's upper
  bound, re-asserts it when something rewrites it, and 'revert' now snapshots and
  restores both ceiling nodes as well.
* New TOP_INDEX (default 44): the slowest OPP, used only when the ladder is unreadable.
  The thermal brake now works there too - at/above TEMP_MAX the floor goes to index 44
  instead of the loop silently doing nothing.
* OFFLINE mode is detected once (ladder_available) and reported by 'status', which also
  prints the live upper bound and warns when it is not the top OPP ("GED will not go
  above this"). 'probe'/'verify' judge a floor+ceiling index 0 as a pin at the top OPP
  instead of "cannot be judged".
* Fixed: 'preset max' passed CEIL_HZ=1600000 (a kHz value that needs the ladder) to the
  ceiling writer; the ceiling intent is now expressed as index 0.
* Fixed: 0 kHz wording throughout ('floor moves to 0 kHz while busy'), and index 0 is
  described as "the top OPP".
* Tests: 29 host cases - offline index rules (top/slowest only, mid-ladder refused),
  cached ladder detection, preset values including the ceiling field, plus everything
  from v11.4.

v11.4 (GPU presets: max / boost / stock)
* New `gpufix.sh preset NAME`, the one command that matters:
    max    MODE=floor, TOP_HZ=0  -> floor = the fastest OPP (1600 MHz) all the time,
           every app, every screen state. Whole-system maximum performance.
    boost  MODE=adaptive, TOP_HZ=1200000 -> 390 MHz idle, 1200 MHz while busy (default).
    stock  MODE=off -> release the floor, stock behaviour.
  The preset writes the config (other keys and comments are kept) and applies the floor at
  once when run as root, so no reboot and no hand-editing is needed.
* TOP_HZ=0 now means "the fastest OPP this driver publishes" instead of being treated as
  nonsense. Combined with MODE=floor that pins floor == ceiling == top OPP, which is what
  "max performance always" actually is; `status` says so explicitly with a `pin:` line.
* New HOT_HZ (default 0 = MIN_HZ): floor used while the battery is at/above TEMP_MAX. Set
  e.g. HOT_HZ=900000 to stay fast-but-safe instead of dropping to stock when hot.
* INTERVAL default 2 -> 1 s so the floor reacts within a second.
* Fixed: the governor trusted a cached OPP index, so when the vendor power HAL rewrote
  custom_boost_gpu_freq the loop did NOT put it back (reproduced in simulation). It now
  re-reads the node every tick and corrects it; a write that keeps failing is logged
  once a minute instead of silently.
* Fixed: `status` reported `plan: level 44 (390000 kHz)` while MODE=floor TOP_HZ=0 was
  actually asking for the top OPP (0 was being rewritten to MIN_HZ). 0 now passes through.
* Fixed: `probe` called a pinned GPU "flat at the floor, proves nothing"; it now says
  "held at the ceiling" and PASSes. It also compares against the floor this module asked
  for and reports when something outside these nodes is holding the clock down.
* Fixed: `preset` echoed the internal mode name instead of the preset name; node reads
  no longer print "cannot open" noise under dash.
* Fixed: service.sh launched gpufix.sh without its `boot` argument, so the loop never
  started from the main module (the standalone module was unaffected).
* Fixed: the standalone module reused the main patch's /data/adb/fod state; it now uses
  /data/adb/gpufix (GPUFIX_STATE overrides), so the two never edit each other's config.
* Tests: 27 host cases (bash + dash) covering presets, config rewriting, plan modes and
  heat, sticky/hold, OPP index resolution, and that the two gpufix.sh copies are identical.

v11.3 (load-following GPU governor, opt-in)
* New gpufix.sh: an adaptive GPU floor, not a static one. It samples GED's own load
  counter (/sys/kernel/ged/hal/gpu_utilization) every INTERVAL s and moves the boost
  floor: MIN_HZ (390 MHz, stock) while idle, TOP_HZ (1200 MHz) while load >= LOAD_ON %
  and for HOLD_S afterwards. MODE=floor keeps it raised, MODE=off always releases.
  The 1600 MHz ceiling and gpu_dvfs_enable are never touched, so the GPU still scales
  by demand inside the window and still idles at 390 MHz - this is a floor, not a lock.
* Why: gpu_dvfs_enable=1 and [GPU-LimitC] CeilingIndex=0 on this device mean nothing is
  pinned, but boost_gpu_enable=0 with gpu_cust_boost_freq=390000 makes GED's boost path
  a no-op, so the clock only leaves 390 MHz when GED itself sees sustained 3D work.
* Commands: status (report + what the governor would do now), probe/verify (frequency
  and load sampling with PASS/FAIL), apply [hz], release, run, revert.
* `apply` resolves the requested frequency against the live OPP ladder
  (/proc/gpufreqv2/gpu_working_opp_table, GED ladder as fallback) and writes the ladder
  index to /sys/kernel/ged/hal/custom_boost_gpu_freq, syncing gpu_cust_boost_freq and
  boost_gpu_enable=1. It refuses without root, without a readable ladder, at/above
  TEMP_MAX, or when the target is not above the floor. The governor releases the floor
  at TEMP_MAX and exits cleanly (releasing first) when ENABLED is set back to 0.
* Snapshot (/data/adb/fod/gpu.orig) + revert; all written values are module parameters
  or GED nodes, so a reboot also restores stock.
* In the main patch it is OFF by default (ENABLED=0 in /data/adb/fod/gpu.conf);
  service.sh starts `gpufix.sh boot`, which does nothing until you enable it.
* New /gpumod: a standalone Magisk module (GPU-DVFS-X6886, id gpu_dvfs_x6886) that ships
  the same gpufix.sh with the governor on, own state dir /data/adb/gpufix, own
  uninstall.sh that restores the nodes. The release workflow publishes it as a second
  asset (GPU-DVFS-X6886-<version>-<sha>.zip) and fails if the two gpufix.sh copies drift.
* customize.sh creates /data/adb/fod/gpu.conf once and addkeys the new options;
  diag.sh reports the GPU block and gpu.log.
* Host-side tests: OPP ladder resolution (wrong index = wrong frequency), GED fallback
  format, sticky/hold logic of the governor, refusal without a ladder, and that both
  gpufix.sh copies stay identical.
